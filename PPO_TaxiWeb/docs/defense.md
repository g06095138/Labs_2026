# Кратко для защиты
1. Идея: сайт небольшой службы такси, три роли; автоматического поиска маршрута и оплаты нет.
2. Формула: 150 + 4×30 = 270 рублей. Требование Т-Б1 → QuoteService.Calculate → Quote_ComfortFourKm. В SQL деньги — 27000 копеек.
3. Use Case отвечает «кто что делает», компоненты — «какие части и зависимости», классы — «объекты и операции кода», ER — «какие данные и связи хранятся».
4. Domain не знает БД и браузер. Application связывает сценарии. Infrastructure сохраняет атомарно. Blazor показывает ввод и результат.
5. SRP: изменение внешнего вида не меняет формулу. DIP: Application зависит от ITaxiStore, SQLite реализует интерфейс.
6. Почему транзакция? Нельзя назначить водителя без изменения его доступности; нельзя завершить поездку и оставить водителя занятым при частичном сбое.
7. Почему UNIQUE по активному водителю? Одних проверок свободного водителя в интерфейсе недостаточно: два диспетчера могут действовать одновременно.
8. Цена — снимок, чтобы изменение тарифов впоследствии не меняло старые заказы. Повторное сравнение не создаёт заказов.
9. Cookie подписана сервером; пользователь не выбирает роль из списка. Водитель фильтруется по driver_id, клиент — по client_id. Кнопка не является защитой сама по себе.
10. Проверки: 29 xUnit, 15 браузерных утверждений и повторное открытие после перезапуска. Это результаты локального стенда, не нагрузочные испытания и не приёмка преподавателя.
11. Отличия от «Финдиректора» перечислены в adaptation.md. Финансовые месяцы и задолженность заменены сценариями такси; исходный архив лектора отсутствовал.
