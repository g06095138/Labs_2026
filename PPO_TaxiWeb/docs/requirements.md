# ЛР1. Спецификация сайта «Служба такси»
## Цель и границы
Сайт небольшой службы: клиент оценивает поездку по трём тарифам и оформляет заказ; диспетчер назначает свободного водителя; водитель начинает и завершает поездку. База переживает перезапуск. Без геокодинга, карт, оплаты, отмены и динамических коэффициентов. Дистанция — ручной ввод, а не вычисленный маршрут. Только RUB; даты хранятся в UTC. Экранное обновление — по кнопке, без обещания realtime.

## Словарь и объекты
Заказ — заявка клиента с маршрутом, фиксированной ценой и статусом. Тариф — базовая цена и цена километра. Оценка — несохранённый результат сравнения тарифов. Клиент — владелец заказов. Диспетчер — оператор назначения. Водитель — исполнитель с признаком доступности. Активный заказ — Assigned или InProgress. Данные доступа — логин, хеш пароля и серверная роль.

## Требования
Т-Ф1. Оценить один маршрут по всем активным тарифам, показать базовую, переменную и итоговую стоимость рядом.
Т-Ф2. Создать заказ: ФИО, телефон, адрес подачи, адрес назначения, расстояние, тариф. Заказ принадлежит вошедшему клиенту; цена и её компоненты зафиксированы на сервере.
Т-Ф3. Диспетчер видит все заказы и свободных водителей; назначает одного исполнителя атомарно.
Т-Ф4. Водитель видит только свои активные заказы, начинает и завершает их. Клиент видит только свои заказы.
Т-Ф5. Сохранение в SQLite: создание, список, открытие, обновление состояния без дубликатов; ошибки полей не изменяют БД.
Т-Ф6. Повторная оценка независима; изменение входа скрывает старую оценку. Нельзя оформить заказ по устаревшему результату. Сервис создания заново проверяет вход и цену.
Т-Ф7. Вход по логину/паролю; клиент, диспетчер и водитель проверяются сервером. Самостоятельная регистрация и управление пользователями вне границ.

## Правила
Т-Б1. Decimal: base + distance × rate; округление до копейки AwayFromZero. При 0.01 × 0.50 получается 0.005.
Т-Б2. Created → Assigned → InProgress → Completed; другие переходы запрещены.
Т-Б3. Только Created и свободный водитель допускают назначение; один активный заказ у водителя. Завершение освобождает исполнителя в той же транзакции.
Т-Б4. ФИО 1…150 символов; телефон 1…50; адреса 1…500. Расстояние 0.01…1000, не более двух знаков. Тариф активен, цены 0…1 000 000 с точностью копейки.
Т-Б5. Цена, базовая цена и ставка фиксируются при создании. Смена статуса не меняет стоимость.
Т-Б6. Ключи постоянные; повторная команда назначения/перехода не создаёт второй заказ и отклоняется при неверном статусе. Отдельный повторный Create означает новый заказ.
Т-Б7. Разрешения проверяются и в Application, и при отображении UI; роль нельзя передать из формы создания заказа.

## Сценарии: ввод → действие → результат / отказ
С1 Оценка/пересчёт: адреса и расстояние → «Сравнить тарифы» → таблица цен; при ошибке поле и причина, старой оценки нет. Изменение параметров очищает оценку.
С2 Оформление: клиент, валидный маршрут, выбранный тариф → «Создать заказ» → один заказ Created с ценой; при ошибке/чужой роли — отказ без записи.
С3 Назначение: диспетчер, ID заказа, ID свободного водителя → назначить → Assigned и занятый водитель одной транзакцией; конфликт/нет свободных — отказ.
С4 Выполнение: текущий водитель, его заказ → начать/завершить → допустимый статус, при завершении свободен; чужой заказ/неверный статус — отказ.
С5 Хранение и открытие: пользователь → обновить список/открыть заказ → сохранённые поля, допустимые для роли; неизвестный ID или чужие данные — отказ. После перезапуска те же данные.
С6 Вход/выход: логин и пароль → вход → серверная cookie с ролью; неверные данные — общее сообщение, доступа нет. Выход завершает сессию.
