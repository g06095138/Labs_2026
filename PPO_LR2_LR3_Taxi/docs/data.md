# ЛР2. Сохраняемые данные финансовых планов

## 1. Назначение
Логическая модель для ЛР4. Отдельный финансовый план службы такси не является заказом поездки. Сохраняются исходные входы; вычисленные отчёты и сравнения не сохраняются. В ЛР2 SQL-типы не требуются; в ЛР3 репозитория ещё нет.

## 2. Сущности, поля и ключи
| Сущность | Поле | Смысл / ограничение |
|---|---|---|
| Plan | Id | PK, постоянный непустой UUID |
| Plan | Name | Непустое после trim название, до 200 символов |
| Plan | InitialCash | Исходные деньги, неотрицательные, точность копейки |
| MonthPlan | PlanId | FK → Plan.Id; часть составного PK |
| MonthPlan | Number | 1/2/3; часть составного PK; уникален в плане |
| MonthPlan | Quantity | Целое число поездок Q≥0 |
| MonthPlan | Price | Средняя цена поездки P≥0, копейки |
| MonthPlan | VariableCost | V≥0 на поездку, копейки |
| MonthPlan | FixedCost | F≥0 на месяц, копейки |
| MonthPlan | PaymentPercent | A — целый процент 0…100 |

Связь: Plan содержит ровно три MonthPlan; каждый MonthPlan принадлежит ровно одному Plan. Ключ (PlanId,Number) устраняет повтор номера в плане. Он сам по себе не гарантирует наличие всех трёх месяцев: прикладная валидация и атомарное сохранение обязаны обеспечивать набор {1,2,3}. В диаграмме точная кратность 3 указана дополнительно к связи 1:N.

## 3. Правила сохранения и открытия
Сохранить план и все месяцы одной транзакцией. Повторное сохранение того же Id обновляет данные без дубликатов и не меняет другой план. Не хранить CurrentPayment, ClosingCash, Debt или агрегаты: они рассчитываются из входов, чтобы не рассинхронизироваться при изменении формулы/параметров.

При открытии нужно точно восстановить денежные входы, номера месяцев и Id. Входы не зависят от справочника тарифов сайта: P — ручная плановая средняя цена, не ссылка на текущий тариф. Для воспроизведения расчёта достаточно сохранённых входов и версии правил П-Б1–П-Б10.

ЛР4 уточнит физическую SQLite-схему, SQL-типы, FK и транзакционную реализацию. Будущие денежные входы можно хранить целыми копейками; выбор SQL-типов не выдаётся за готовую БД. Файлов БД в комплекте ЛР2–3 нет.

## 4. Что не сохраняется
Результаты, актуальность экранного расчёта, выбранная пара сравнения, рассчитанная задолженность, отрицательные остатки. Пользовательская сессия/права руководителя проектируются вместе с Blazor UI; в учебной консоли этой роли соответствует пользователь, запускающий процесс. Это не промышленная авторизация.
