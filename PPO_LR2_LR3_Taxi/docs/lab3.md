# ЛР3. Прогноз и финансовые показатели
## Объём
Финансовое ядро месяца, валидация плана, прогноз трёх месяцев, сравнение двух планов, консоль и xUnit. Источник входов — контрольные планы в коде либо JSON. Ни реальное хранилище, ни веб-экран финансового планирования не входят в ЛР3.

## Реализация
| Требование | Операция / артефакт |
|---|---|
| ЛР3-Ф1 | ForecastService.Forecast: проверка всех входов, месяцы 1–3, initialDebt=0 и перенос C/D |
| ЛР3-Ф2 | FinancialCalculator.CalculateMonth, Summarize: месячные показатели и четыре итога |
| ЛР3-Ф3 | ComparisonService.Compare: два независимых прогноза и итоги рядом |
| ЛР3-А1 | Формулы в Domain, цикл в Application, форматирование в Console |
| ЛР3-Т1 | Тесты 0/50/100%, пустых продаж, нулевых денег, ошибочного A, разных месяцев |
| ЛР3-Т2 | Тесты переноса, отрицательного C, сравнения, повторов и неизменности входов |
| ЛР3-Т3 | Отказы для initialCash<0, пустого имени, неполного/дублирующего/неверного набора месяцев |
| ЛР3-Д1 | Обновлённая requirements.md: операции, имена тестов, подтверждённые и будущие части |

## Что не заявляется
Сохранение и открытие после перезапуска SQLite (ЛР4), скрытие результата при правке в браузере и финансовый Blazor UI (ЛР5). Наличие интерфейса IPlanRepository не означает выполненное хранение. Исходный архив ядра лектора не предоставлен; реализовано самостоятельное ядро по его правилам и контрольным числам. Чужие исходные тесты не запускались.

Фактические команды, результаты и ограничения будут зафиксированы в validation.md после запуска. Метки lab2/lab3 в GitLab создаёт реальная процедура сдачи, а не генератор документов.
