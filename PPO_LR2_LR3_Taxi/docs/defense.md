# Коротко для защиты ЛР2–ЛР3
1. ЛР2 — проектирование; ЛР3 — реализация и тесты расчёта. Продолжается финансовая ЛР1, не схема операционных заказов.
2. Услуга такси — поездка. Q=500, P=300 → R=150000. Q×V=50000, F=70000 → прибыль=30000.
3. При A=50% сразу поступает 75000; в месяце 2 добавляется долг 75000. Деньги 5000→35000→65000. Долг третьего месяца отдельно: 75000, к C3 не прибавляется.
4. Domain знает формулы. Application знает порядок трёх шагов. Console знает только ввод и оформление результата. Infrastructure и Blazor пока спроектированы.
5. SRP — не смешиваем расчёт с экраном; DIP — Application объявляет IPlanRepository, а будущий SQLite его реализует.
6. ER хранит Plan и MonthPlan, не отчёты. Нужны PK Plan.Id и составной PK (PlanId,Number); в плане ровно три месяца.
7. Финансирование — максимум нехватки: для C=-70000/-40000/-10000 нужно 70000, а не 120000.
8. decimal и AwayFromZero: 0.01×50%=0.005 → S=0.01, D=R−S=0. Нельзя округлять долг независимо и терять копейку.
9. Повторный Forecast не продолжает прошлый результат: стартует из InitialCash и debt=0. Входы и результаты неизменяемые.
10. Сохранение/открытие БД — следующая работа. Чтение examples/*.json не является реализацией репозитория.
