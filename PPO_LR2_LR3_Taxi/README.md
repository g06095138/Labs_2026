# ЛР2–ЛР3. Финансовое планирование службы такси
Продолжение последней финансовой ЛР1 из `PPO_LR1_Taxi`, а не раннего операционного проекта заказов. Поездка — плановая услуга; сохраняются все финансовые правила П-Б1–П-Б10 лектора. Классическая схема: требования → проектирование → расчёт и тесты.

## Что сделано
**ЛР2:** design.md (архитектура, пять контрактов, SRP/DIP, ручной расчёт), data.md (логические данные и ключи), три диаграммы с исходниками и изображениями: компоненты, классы, ER.
**ЛР3:** C# Domain/Application/Console, валидация, прогноз трёх месяцев, сравнение, xUnit, актуальная requirements.md с именами операций/тестов. Успешность проверок — docs/validation.md.

Реальное хранение финансовых планов — ЛР4, финансовый Blazor UI — ЛР5. В этом решении нет сайта с новым экраном и нет реальной реализации репозитория. Существующий сайт оформления такси не меняется и не требуется для запуска расчёта. Чтение JSON — только ввод контрольных планов, не сохранение данных пользователем.

## Какие файлы читать и сдавать
- reports/ЛР2_Такси_Проектирование.docx — отчёт Word по ЛР2.
- reports/ЛР3_Такси_Прогноз_и_тесты.docx — отчёт Word по ЛР3.
- docs/design.md, docs/data.md — обязательные документы ЛР2.
- docs/diagrams/components.*, domain.*, er.* — обязательные схемы ЛР2; domain актуальна для кода ЛР3.
- docs/requirements.md — актуальная спецификация и таблица соответствия.
- src/ — Domain, Application, Console; tests/ — xUnit.
- examples/ — планы 0/50/100%, разные месяцы, ошибка A=101.
- docs/validation.md, docs/test-results/ — фактические проверки.
- docs/artifacts.md — соответствие всем пунктам ЛР2/ЛР3.

PNG — посмотреть/вставить в Word, SVG — масштабировать без потери качества, PDF — печать, PUML — редактируемый исходник PlantUML. ER — логическая модель, SQL-типы по этой работе не требуются.

## Запуск на Mac / Windows / Linux
Нужен **.NET SDK 10**, не только Runtime. global.json закрепляет 10.0.403 с разрешением более новых feature-band версий .NET 10. На Mac M-серии используйте SDK Arm64, на Intel — x64. В VS Code откройте папку, где лежит **TaxiFinance.sln**; расширение C# Dev Kit удобно, но для терминала необязательно.

Из этой папки:
```sh
dotnet restore TaxiFinance.sln --locked-mode
dotnet build TaxiFinance.sln -c Release --no-restore
dotnet test TaxiFinance.sln -c Release --no-build
```
Контрольная демонстрация (0%, 50%, 100%, затем сравнение):
```sh
dotnet run --project src/TaxiFinance.Console -c Release --no-build -- demo
```
Один план:
```sh
dotnet run --project src/TaxiFinance.Console -c Release --no-build -- forecast examples/plan-b.json
```
Сравнить:
```sh
dotnet run --project src/TaxiFinance.Console -c Release --no-build -- compare examples/plan-a.json examples/plan-b.json
```
Машиночитаемый результат: добавить `--json` после пути(ей). План можно изменить в VS Code как JSON; это редактирование входного файла, не UI будущего сайта. Денежный разделитель в JSON — точка, а не запятая. Не удаляйте Id и три месяца. Пересчёт каждый раз начинается заново из файла.

Проверка отказа (ожидаемый код завершения **2**, это не ошибка установки):
```sh
dotnet run --project src/TaxiFinance.Console -c Release --no-build -- forecast examples/invalid-percent.json
```
Ожидается сообщение поля `Months[2].PaymentPercent`: «Введите целый процент от 0 до 100».

Дополнительная чёрноящичная проверка консоли: `python3 scripts/check_console.py`. Требуется только Python 3; сам финансовый модуль не зависит от Python, Java, браузера, SQLite или веб-сервера. После чистой сборки проверка создаёт временные файлы и удаляет их.
