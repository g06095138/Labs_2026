# Проверка ЛР3 оператора связи

Проверено 11 ноября 2026 года в Linux x64, .NET SDK 10.0.403 / runtime 10.0.14. Проект использует .NET 10 без платформенных API. Запуск на macOS описан в README; интерактивная работа VS Code на компьютере пользователя в этой проверке не выполнялась.

## Воспроизведение

Из папки с `TelecomFinance.sln`:

```bash
dotnet restore TelecomFinance.sln --locked-mode
dotnet build TelecomFinance.sln -c Release --no-restore
dotnet test TelecomFinance.sln -c Release --no-build --logger "trx;LogFileName=finance-tests.trx" --results-directory docs/test-results
dotnet run --project src/TelecomFinance.Console -c Release --no-build -- demo
python3 scripts/check_console.py
```

Python нужен только для дополнительных консольных проверок. Программа и xUnit работают без Python. Зависимости .NET зафиксированы в `packages.lock.json`.

## Результаты

- Восстановление зависимостей в locked mode прошло успешно.
- Сборка Release и сборка консольного проекта Debug: 0 ошибок, 0 предупреждений.
- Автоматические тесты: **72** пройдено, 0 ошибок, 0 пропусков. Машинный протокол: [finance-tests.trx](test-results/finance-tests.trx).
- Проверки с запуском отдельного процесса консоли: **19** пройдено, 0 ошибок. Протокол: [console-checks.json](test-results/console-checks.json).
- Проверен запуск из заново распакованного архива: locked restore и демонстрация в Debug проходят успешно.
- Вывод готовой демонстрации: [console-demo.txt](test-results/console-demo.txt).

В xUnit проверяются числовые ожидания сценариев 0/50/100%, отсутствие клиентов, абонплата при нуле минут, нулевые деньги, разные параметры месяцев, перенос задолженности и отрицательного остатка, максимальный дефицит, повторный расчёт, изменения плана, независимость сравнения и неизменность входов. Проверяются округление копеек, убыточный тариф, неверные суммы, числа клиентов/минут, процент, UUID, название, набор месяцев и календарь.

Консольные проверки дополнительно подают JSON-файлы и проверяют коды завершения, структуру ответа, неизвестные и пропущенные поля, повторные ключи, дробные значения целых параметров и отсутствие файла. Для шести допустимых примеров используются заранее заданные ожидаемые суммы; они не вычисляются через проверяемый код.

## Граница проверки

Тесты рассчитаны на реализованное ядро ЛР3. Реальное хранение и восстановление планов после перезапуска, SQL-схема и интерфейс сайта относятся к следующим этапам и не объявляются проверенными. Чтение исходного JSON не заменяет проверку хранилища ЛР4. Тесты исходного стартового проекта преподавателя не предоставлены; запускается самостоятельный набор проверок по его требованиям.
