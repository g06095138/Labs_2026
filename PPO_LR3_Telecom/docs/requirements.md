# Требования. ЛР3 — финансовый прогноз оператора связи

## 1. Цель и границы

Оценить, достаточно ли оператору связи денег на три месяца обслуживания абонентов, даже при положительной прибыли. Построить прогноз заново по входному плану и сопоставить итоги двух независимых планов.

Модель относится к одной компании и одной агрегированной услуге — месяцу обслуживания абонента. Все плановые затраты оплачиваются в текущем месяце. Остаток неоплаченных счетов полностью поступает в следующем. Налоги, кредитование, порядок платежей внутри месяца и детализация отдельных звонков не моделируются. Начальная задолженность равна нулю. Неоплаченная выручка третьего месяца остаётся долгом и не добавляется к деньгам.

ЛР3 реализует расчёт, сравнение и проверки. Постоянное хранение относится к ЛР4, веб-интерфейс — к ЛР5. Связь с курсовой и изменения прежней ER-схемы изложены в [coursework-adaptation.md](coursework-adaptation.md).

## 2. Словарь

| Термин | Значение |
|---|---|
| Выручка | Стоимость обслуживания абонентов, начисленная за месяц |
| Маржинальный доход | Выручка за вычетом переменных затрат |
| Прибыль | Выручка минус все расходы; не равна денежному остатку |
| Поступления | Оплата текущих счетов и долг прошлого месяца, поступившие сейчас |
| Дебиторская задолженность | Начисленная выручка, пока не оплаченная клиентами |
| Кассовый разрыв | Отрицательный прогнозный денежный остаток |
| Оплачиваемые минуты | Агрегированные минуты, за которые начисляется плата после применения правил тарифа |

## 3. Объекты и ограничения входа

**FinancialPlan:** `Id` — непустой UUID; `Name` после удаления пробелов по краям содержит 1…200 символов; `InitialCash` — неотрицательные деньги до первого месяца; `StartYear`, `StartMonth` — начало календарного периода; `Months` — ровно три набора параметров с уникальными номерами 1, 2, 3.

**MonthParameters:** `Number`, `ActiveClients`, `AvgBillableMinutesPerClient`, `PricePerMinute`, `MonthlyFeePerClient`, `VariableCostPerClient`, `OperationalCosts`, `PaymentPercent`.

Все денежные входы — decimal от 0 до 10^12 ₽ включительно, не более двух знаков после запятой. Число абонентов и средние оплачиваемые минуты — целые 0…10^6. Процент оплаты — целое 0…100. Цена ниже переменных затрат, нулевая цена, убыток и отсутствие продаж допустимы. `StartMonth` — 1…12. Год каждого из трёх календарных месяцев — 2020…2099. Например, старт в ноябре 2099 отклоняется: третий месяц вышел бы за предел 2099 года. Технические верхние границы делают диапазон входов явным и не заменяют проверку переполнения.

**Результат:** три `MonthReport` и `FinancialSummary`. В каждом месяце показаны начальные деньги/долг, выручка, переменные расходы, маржинальный доход, общие расходы, прибыль, текущая оплата, поступления, конечные деньги и долг. Итог содержит общую прибыль, конечные деньги, конечный долг и требуемое финансирование. `PlanComparison` содержит две подписанные стороны с идентификаторами и итогами.

## 4. Правила расчёта

Адаптация входов: `Q = ActiveClients`, `P = AvgBillableMinutesPerClient × PricePerMinute + MonthlyFeePerClient`, `V = VariableCostPerClient`, `F = OperationalCosts`, `A = PaymentPercent`.

| Код | Правило |
|---|---|
| П-Б1 | R = Q × P; переменные расходы = Q × V; маржинальный доход = R − Q × V |
| П-Б2 | E = Q × V + F; прибыль = R − E |
| П-Б3 | S = Round(R × A / 100, 2, AwayFromZero); D = R − S |
| П-Б4 | Поступления = S + начальный долг; до первого месяца долг равен 0 |
| П-Б5 | C = начальные деньги + поступления − E; C и D переносятся в следующий месяц |
| П-Б6 | При C < 0 выводится «Не хватает денег»; расчёт продолжается без автоматического кредита. C = 0 допустимо |
| П-Б7 | Общая прибыль = сумма прибыли трёх месяцев; финансирование = max(0, −min(C1,C2,C3)); D3 отдельно от C3 |
| П-Б8 | Ограничения входа из раздела 3; отрицательные начальные деньги запрещены, отрицательные перенесённые остатки допустимы |
| П-Б9 | decimal; оплата округляется AwayFromZero; долг считается вычитанием, чтобы не терять копейки |
| П-Б10 | Постоянный непустой UUID, непустое название, три уникальных номера 1/2/3 |

## 5. Сценарии и отказы

### С1. Создать или изменить план и получить прогноз

**Ввод:** название, UUID, начальные деньги, начало календаря, три набора параметров. **Действие:** вызвать `ForecastService.Forecast`. **Результат:** три строки и итоги с переносом C/D. При изменении создаётся новый вариант входных значений; пересчёт начинается с C0 и нулевого долга, прежний результат не используется. **Отказ:** указаны поле и причина, прогноз не выдаётся; например `Months[2].PaymentPercent` вне 0…100, неверный набор месяцев, отрицательные начальные деньги, пустое название, ошибочный календарь. JSON-консоль также отклоняет повреждённый/неполный файл и дробное значение целого поля.

### С2. Сравнить два плана

**Ввод:** два допустимых плана с разными UUID. **Действие:** `ComparisonService.Compare(left,right)`. **Результат:** рядом четыре итоговых показателя каждой стороны, с названиями и идентификаторами. Данные и результаты сторон не влияют друг на друга. **Отказ:** ошибка стороны и поля (`Left.…`/`Right.…`) либо одинаковые UUID. Исходные планы не меняются.

### С3. Сохранить и открыть план — контракт следующего этапа

**Ввод:** допустимый план для сохранения или UUID для открытия. **Действие:** в ЛР4 сохранить исходные данные одной транзакцией, показать список, открыть новым экземпляром хранилища и пересчитать. **Ожидаемый результат:** те же UUID и значения; сохранение с тем же UUID обновляет план без дубликата. **Отказ:** недопустимый план, отсутствующий UUID, ошибка хранилища. Реальное хранилище и проверка после перезапуска не реализуются и не объявляются пройденными в ЛР3.

## 6. Приёмочные примеры, рассчитанные до реализации

Общий ввод для ПР1–ПР3, ПР6–ПР8: старт ноябрь 2026, C0 = 50000 ₽. Каждый месяц: 100 абонентов, 200 оплачиваемых минут на абонента, цена минуты 5 ₽, абонплата 500 ₽, переменные расходы 500 ₽ на абонента, постоянные расходы 70000 ₽. P = 200 × 5 + 500 = 1500 ₽; R = 150000 ₽; переменные расходы = 50000 ₽; маржинальный доход = 100000 ₽; E = 120000 ₽; прибыль месяца = 30000 ₽. Планы для сравнения имеют разные UUID.

|---|---|---|---|
| ПР1 | Общий ввод, A = 0% во всех месяцах | S = 0/0/0; поступления = 0/150000/150000; C = −70000/−40000/−10000; D = 150000/150000/150000. Общая прибыль 90000, C3 = −10000, D3 = 150000, финансирование 70000 | П-Ф2; П-Б1–П-Б7 |
| ПР2 | Общий ввод, A = 50% | S = 75000/75000/75000; поступления = 75000/150000/150000; C = 5000/35000/65000; D = 75000/75000/75000. Общая прибыль 90000, C3 = 65000, D3 = 75000, финансирование 0 | П-Ф2; П-Б1–П-Б7 |

После изменения первого плана его C = 0/30000/60000, финансирование 0; второй план прежний | П-Ф1, П-Ф3, П-Ф6; П-Б5, П-Б7 |

После будущего открытия все входы и числа должны совпасть. В ЛР3 проверяется только расчёт этого входа | П-Ф4, П-Ф6; П-Б3–П-Б5, П-Б10 |

Дополнительные обязательные проверки ЛР3: разные параметры месяцев; перенос долга; продолжение после отрицательного остатка; повтор и неизменность входных объектов; отрицательные C0, пустое название, недопустимые наборы месяцев. Проверяется округление: при одном абоненте, одной оплачиваемой минуте по 0.01 ₽, нулевой абонплате, V/F = 0 и A = 50% оплата месяца составляет 0.01 ₽, долг 0, C = 0.01/0.02/0.03 при C0 = 0.
