# Адаптация курсовой к ЛР3

## 1. Источник и граница работы

Предметный источник — предоставленная курсовая «БД „Учёт вызовов оператора связи“». Методическое задание — ЛР3 «Прогноз и финансовые показатели» из комплекта «Финдиректор». Курсовая задаёт предметную область, а комплект лабораторных — состав текущей работы, правила финансового прогноза и технологию C# / .NET 10 / xUnit.

## 2. Что действительно описано в курсовой

Разделы 1–3 описывают клиентов, междугородние и международные вызовы, тарифы, направления и платежи. Основные сущности: CLIENTS, CALLS, TARIFFS, COUNTRIES, CITIES, PAYMENTS. Тариф имеет цену минуты, месячную абонплату и бесплатные минуты. Пользователи — клиент, менеджер и администратор.

В разделе 7.2 функция `calc_call_cost` рассчитывает стоимость вызова как `max(ceil(duration_sec / 60) − free_minutes, 0) × price_per_min`. Функция `get_monthly_bill` формирует счёт из абонплаты и стоимости завершённых вызовов. В курсовой используется PostgreSQL и Python/Tkinter. Модель прибыли и расходов оператора на три месяца в ней не определена.

## 3. Что реализует ЛР3

Для будущего сайта оператора проектируется финансовый модуль. Пользователь — руководитель/финансовый менеджер оператора. Он задаёт агрегированные плановые показатели и оценивает прибыль, деньги, долг и нехватку финансирования за три месяца.

Средние **оплачиваемые** минуты — уже подготовленный вход после применения правил тарифа и бесплатных минут. Модуль ЛР3 не тарифицирует отдельные вызовы, не реализует SQL-функции курсовой и не подключает её рабочую БД. Поэтому расчёт прогнозного среднего счёта не подменяет биллинг курсовой.

| Правило преподавателя | Адаптация |
|---|---|
| Количество услуг Q | Число обслуженных абонентов `ActiveClients` |
| Цена услуги P | Средний счёт: `AvgBillableMinutesPerClient × PricePerMinute + MonthlyFeePerClient` |
| Переменные затраты V | Расходы на одного обслуженного абонента `VariableCostPerClient` |
| Постоянные расходы F | Общие постоянные расходы оператора `OperationalCosts` |
| Процент немедленной оплаты A | Доля суммы счетов, оплаченная в текущем месяце `PaymentPercent` |

Цена минуты и абонплата взяты из понятий курсовой; плановые расходы, начальные деньги, средние оплачиваемые минуты и процент оплаты — явно введённые допущения финансовой модели. Они не выдаются за данные, извлечённые из действующей БД.

Средние оплачиваемые минуты здесь задаются целым числом, чтобы цена услуги P оставалась суммой с точностью до копейки при денежных входах с двумя знаками. Это учебное ограничение входа прогноза, а не утверждение о точности всех статистических показателей оператора.

## 4. Отношение к ранее предоставленной ER-модели

Ранее для telecom была перерисована схема FinancialPlan / PlanMonth в нотации Чена. Она содержала календарь, число клиентов, средние минуты, цену минуты, абонплату, операционные расходы и процент оплаты. На том этапе исходный код не анализировался.

Для полного выполнения ЛР3 модель уточняется:

- В план добавлены `InitialCash`, в месяц — `VariableCostPerClient`: без них нельзя получить начальные деньги и маржинальный доход по П-Б1.
- Число клиентов допускает 0, чтобы проверить отсутствие продаж, обязательное для ЛР3-Т1.
- Средние минуты явно означают оплачиваемые после тарифных правил и имеют целый тип.
- `OperationalCosts` — постоянные расходы F; переменная часть считается отдельно.
- Доля оплаты — целое число 0…100 по П-Б8.
- Годы плана и всех трёх календарных периодов ограничены 2020…2099.

Старая отдельная ER-перерисовка не изменяется задним числом; актуальной для этого проекта является спецификация в `docs/requirements.md` и диаграмма классов ЛР3.

## 5. Этапы развития

Сейчас реализуются прогноз, сравнение, консоль и тесты. Ввод из JSON — консольный ввод исходных параметров. Сохранение, обновление по UUID и список планов относятся к ЛР4. Будущий Blazor-интерфейс относится к ЛР5. SQLite для учебного модуля — требование комплекта лабораторных; оно не является заявлением о переносе всей курсовой с PostgreSQL.
